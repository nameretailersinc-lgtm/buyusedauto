# Launch checklist and 90-day growth plan

## Launch blockers

- [ ] Confirm the operator's public identity and add it to About, Terms, and Privacy.
- [ ] Configure `NEXT_PUBLIC_CONTACT_EMAIL`; send and receive a real test message using that inbox.
- [ ] Review the six guides and tool methodologies for accuracy, clarity, and suitable deployment-specific legal/privacy terms. No independent expert review is claimed yet.
- [ ] Connect the intended Vercel project and domain; verify DNS, TLS, apex/preferred-host behavior, and production deployment.
- [ ] Run final browser, internal-link, metadata, structured-data, and Lighthouse checks against production. Record actual findings in `docs/QA.md`.
- [ ] Verify representative pages with Schema.org Validator and Google Rich Results Test. Structured data is descriptive, not a rich-result guarantee.
- [ ] Keep preview deployments out of indexing; check canonical origin and production robots behavior.
- [ ] Add the actual Search Console verification value, verify domain ownership, and submit `/sitemap.xml`.
- [ ] Inspect home, primary calculators, and two guides with Search Console URL Inspection; request indexing where appropriate without assuming a timing guarantee.
- [ ] If analytics is desired, complete the consent and property audit in `docs/MONETIZATION.md` before setting a real GA4 ID.
- [ ] Activate advertising only after actual eligibility/approval, real IDs, and the certified CMP workflow. No page-count threshold promises approval.
- [ ] Add affiliate links only after a real relationship is approved, with tested destinations and visible disclosures.

## Days 1–14: establish a trustworthy baseline

- Publish the focused collection after resolving blockers. Check indexability, sitemap processing, coverage, mobile rendering, and server errors.
- Review calculator behavior with five prospective users completing real tasks: compare two loan offers, estimate total cost, flag inspection concerns, verify a tax input, and prepare an offer. Record confusion, failed tasks, and corrective changes.
- Establish weekly Search Console exports by page and query. Track impressions, clicks, CTR, average position, and indexed canonical URLs without treating position as an outcome by itself.
- Keep a correction log with the affected claim, source, actual review date, and code/content change. Prioritize inaccuracies and unclear assumptions over adding pages.

## Days 15–30: improve the pages people use

- Review queries with impressions but weak engagement. Improve titles and introductions to match the actual page purpose; do not stuff additional variants into headings.
- Ask users whether outputs helped them make a decision. Track task completion only with appropriate consent and without numerical input collection. Use qualitative feedback when analytics is disabled.
- Audit the source directory, external links, keyboard experience, and narrow-screen layout. Check Search Console's real Core Web Vitals once enough field data exists; lab TBT is not INP.
- Fix important discovery gaps with contextual links from existing guides and tools. Avoid indexing filter or query variants.

## Days 31–60: add evidence-driven content

- Select two new guide topics only after query evidence and user questions reveal a gap, such as evaluating a specific history-report discrepancy or preparing for a private-party transfer. Research the exact jurisdiction where rules matter.
- Publish one useful asset that others can cite: a transparent loan-term comparison study using hypothetical inputs, a carefully sourced inspection worksheet, or a reproducible ownership-cost sensitivity analysis. Explain methods and limitations.
- Identify a small set of relevant community organizations, consumer educators, repair shops, and credit unions whose audiences could use the resource. The operator can make personalized outreach offering a useful citation or correction; do not buy links, demand reciprocal links, or mass-email templates.
- Review early financing scenario performance. Merge or noindex pages that fail to add distinct value; do not expand combinations automatically.

## Days 61–90: expand what earns usefulness

- Revisit the strongest user tasks and improve a comparison feature or clarify the most common misunderstood input. Add a regional version only with reliable localized sources and a clear maintenance owner.
- Publish at most two additional well-researched guides if they answer demonstrated gaps. Recheck existing sources and record real editorial updates rather than refreshing dates automatically.
- Evaluate any affiliate partner on relevance, actual service, clear terms, and conversion quality. Maintain a useful unmonetized path through every calculator.
- Review the 90-day dashboard: resolved user issues, tool task success, relevant organic clicks, indexed quality pages, earned referring domains, consent-respecting conversion evidence, and field performance. Set the next quarter's work based on those observations.

## Success criteria

Better user decisions and fewer errors come first. Traffic and revenue are uncertain outcomes. No ranking, backlink, AdSense, or earnings guarantee is made, and no content expansion is justified solely by a desired indexed-page count.
